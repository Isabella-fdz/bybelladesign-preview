Cómo doy forma a cada proyecto.

Un camino claro desde el problema hasta un diseño listo para desarrollo.

  1. 01Entender
  2. 02Diseñar
  3. 03Validar
  4. 04Entregar

  1. /01Entender

    Entender el problema antes de diseñar.

    Entrevistas, datos y el proceso actual del negocio, para saber qué importa y qué se va a medir.

  2. /02Diseñar

    Flujos claros antes que pantallas.

    Flujos, wireframes e interfaz sobre el design system, de cerca con producto e ingeniería.

  3. /03Validar

    Probar con personas reales.

    Pruebas con usuarios y métricas para decidir con evidencia, no con opiniones.

  4. /04Entregar

    Listo para desarrollo.

    Entrego a desarrollo con specs y componentes, y hago QA de lo que se implementa. Con IA, también abro pull requests de interfaz que ingeniería revisa y aprueba.
